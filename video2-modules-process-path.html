Module system

Big idea

A module is just a file. Everything inside it is private unless you export it, and other files must import it to use it. Node has two systems: CommonJS (require / module.exports, the classic default) and ES Modules (import / export, the modern standard).

Analogy

Each file is a house with the curtains closed. Exporting is putting something on the front porch. Importing is walking to a neighbour's porch and picking it up. You can't reach inside their house.

CommonJS in detail

math.jsconst add = (a, b) => a + b;
const sub = (a, b) => a - b;
const SECRET = 42;              // not exported → private to this file

// Option A: export an object of things
module.exports = { add, sub };

// Option B: add properties one at a time
// exports.add = add;
// exports.sub = sub;

app.jsconst math = require("./math");        // .js extension optional in CommonJS
math.add(2, 3);                         // 5

const { add } = require("./math");      // destructure just what you need
add(1, 1);                              // 2

The exports trap (a classic exam question)

exports starts as a shortcut pointing to the same object as module.exports. Node only ever returns module.exports.

exports.hello = "hi";          // ✅ works: adds to the shared object
module.exports = { a: 1 };     // ✅ works: replaces what's exported
exports = { a: 1 };            // ❌ does nothing: you just pointed the shortcut elsewhere

ES Modules in detail

To use ESM in Node, either set "type": "module" in package.json or name files .mjs.

math.jsexport const add = (a, b) => a + b;      // named export
export function sub(a, b) { return a - b; }
export default function multiply(a, b) {  // default export (max one per file)
  return a * b;
}

app.jsimport multiply, { add, sub } from "./math.js";  // default first, then { named }
import * as math from "./math.js";               // everything as one object
import fs from "fs";                             // core modules work too
import express from "express";

What actually happens when you require

  1. Resolve: work out the file path (core module? ./ path? look in node_modules?).
  2. Wrap: Node wraps your file in a function: (function (exports, require, module, __filename, __dirname) { …your code… }). That's why those five names exist without being declared, and why your variables stay private.
  3. Run the file once.
  4. Cache: the result is stored. Requiring the same file again returns the cached object and does not re-run the code.

See the cache yourself New

counter.jsconsole.log("counter.js is running");
let count = 0;
module.exports = { next: () => ++count };

app.jsconst a = require("./counter");
const b = require("./counter");   // cached: counter.js does NOT run again
console.log(a === b);             // true: the very same object
console.log(a.next(), b.next());  // 1 2: they share count

counter.js is running
true
1 2

That’s why a module is a natural home for shared things, like one database connection that every file reuses.

Exam traps
  • require("math") without ./ looks in node_modules, not your folder: "Cannot find module".
  • Mixing systems: using require in a file with "type": "module" gives "require is not defined in ES module scope".
  • Forgetting to export: the import gives undefined and calling it says "is not a function".
  • Code at the top of a module runs only once, however many times it's required.
Remember
  • File = module = private by default.
  • CJS: module.exports + require. ESM: export + import with .js extension.
  • Never reassign exports = …; use module.exports = ….

Process module: process.argv

Big idea

process is a global object describing the currently running program. You don't need to require it. Its star feature on your syllabus is process.argv: an array of the words typed in the terminal to start the program, which lets you build command-line tools.

Analogy

process is your program's ID badge and control panel: who launched it, with what instructions (argv), with what secret settings (env), and a big red stop button (exit).

The shape of process.argv

greet.jsconst args = process.argv.slice(2);   // drop node + script path
const name = args[0];
const age = Number(args[1]);          // argv values are ALWAYS strings

if (!name) {
  console.log("Usage: node greet.js <name> <age>");
  process.exit(1);                    // stop; non-zero code = failure
}
console.log(`Hi ${name}, next year you'll be ${age + 1}`);

$ node greet.js Asha 21
Hi Asha, next year you'll be 22
slice(2)returns a new array starting from index 2: only what the user typed. Number(...)without it, "21" + 1 would give "211". process.exit(1)ends the program immediately. 0 = success, any other number = error.

Classic exam program: a command-line calculator

calc.jsconst [op, a, b] = process.argv.slice(2);   // destructure the args
const x = Number(a);
const y = Number(b);

if (isNaN(x) || isNaN(y)) {
  console.log("Please pass two numbers");
  process.exit(1);
}

switch (op) {
  case "add": console.log(x + y); break;
  case "sub": console.log(x - y); break;
  case "mul": console.log(x * y); break;
  case "div":
    if (y === 0) { console.log("Cannot divide by zero"); process.exit(1); }
    console.log(x / y); break;
  default: console.log("Unknown operation. Use add, sub, mul or div");
}

Environment variables in practice

Put secrets in a .env file (never commit it), e.g. DATABASE_URL="postgresql://...". Prisma reads .env automatically. For your own code, Node 20.6+ can load it with node --env-file=.env app.js, or use the dotenv package: require("dotenv").config().

Load .env without a package New

.env# never commit this file: add .env to .gitignore
PORT=4000
API_KEY="abc123"

// Option 1: let Node load it before your code runs
//   node --env-file=.env app.js
// Option 2: load it from code
process.loadEnvFile();                  // reads ./.env by default
const port = Number(process.env.PORT ?? 3000);
console.log(`Starting on ${port}`);

Both are stable from Node 24.10 (and 22.21). A variable already set in your shell wins over the file. --env-file stops with an error if the file is missing; use --env-file-if-exists=.env when it’s optional.

Reading flags with util.parseArgs New

Real command-line tools take flags like --name Asha or -s. Instead of picking them out of argv by hand, use the built-in parser.

greet.jsconst { parseArgs } = require("node:util");

const { values, positionals } = parseArgs({
  options: {
    name:  { type: "string", short: "n", default: "stranger" },
    shout: { type: "boolean", short: "s" }
  },
  allowPositionals: true
});

let msg = `Hello, ${values.name}`;
if (values.shout) msg = msg.toUpperCase();
console.log(msg, positionals);

$ node greet.js --name Asha -s extra
HELLO, ASHA [ 'extra' ]

An unknown flag such as --colour throws an error, which is usually what you want: typos get caught.

Ending a program cleanly New

process.exit(1)

Stops immediately. Anything still waiting, like a file write or a log line, can be lost.

process.exitCode = 1

Records the exit code, lets Node finish its pending work, then exits on its own. Prefer this in real programs.

// Ctrl+C sends the SIGINT signal. Clean up before leaving.
process.on("SIGINT", () => {
  console.log("\nSaving and shutting down…");
  server.close(() => process.exit(0));
});
Also handyGives you

Exam traps
  • Your first argument is argv[2], not argv[0].
  • Every argv value is a string. Convert numbers.
  • process.cwd() depends on where you ran the command; __dirname is always the file's own folder.

Path module: path.join

Big idea

File paths look different on different systems: Windows uses \, Mac and Linux use /. The path module builds and takes apart paths correctly for whatever OS the code runs on. Never glue paths together with +.

Analogy

Giving directions: "Go to the kitchen, then the cupboard, then the top shelf." path.join turns those steps into a correct address, and it understands "go back one room" (..).

const path = require("path");

path.join("users", "asha", "notes.txt");
// "users/asha/notes.txt"   (Windows: "users\\asha\\notes.txt")

path.join(__dirname, "data", "todos.json");
// "/home/me/project/data/todos.json"  ← the most common use of all

path.join("/a/b", "../c");        // "/a/c"     .. goes up one folder
path.join("a", "./b", "//c/");    // "a/b/c/"   tidies extra slashes and ./

join vs resolve

path.join

Glues pieces together in order and tidies. Can return a relative path.

path.join("a", "/b", "c")
// "a/b/c"

path.resolve

Works right-to-left until it has an absolute path; a segment starting with / resets it.

path.resolve("a", "/b", "c")
// "/b/c"

Why __dirname matters

// ❌ Relative to wherever you typed "node" — breaks if run from another folder
fs.readFileSync("data.json");

// ✅ Relative to this file's own folder — always works
fs.readFileSync(path.join(__dirname, "data.json"));

Don’t let users escape your folder New

If part of a path comes from a user (a URL, a form, argv), .. can walk out of the folder you meant to share, and path.join happily follows it.

const path = require("node:path");
const PUBLIC = path.join(__dirname, "public");

function safePath(userInput) {
  const full = path.resolve(PUBLIC, userInput);   // absolute, with .. applied
  if (!full.startsWith(PUBLIC + path.sep)) {      // still inside public/ ?
    throw new Error("Path not allowed");
  }
  return full;
}

safePath("img/cat.png");        // ✅ /home/me/project/public/img/cat.png
safePath("../../etc/passwd");   // ❌ throws

This attack is called path traversal. Express’s express.static protects you from it, but you need this check whenever you build paths by hand, as you will with the raw http server in video 3.

Exam traps
  • "folder" + "/" + "file" breaks on Windows. Use path.join.
  • extname includes the dot: ".js", not "js".
  • In ES modules there's no __dirname; use import.meta.dirname (Node 20.11+).

Mini project: file-info CLI New

process.argv + path · about 15 minutes

Describe any path from the terminal

Write fileinfo.js. It takes one path as an argument and prints the file’s name, extension, folder, absolute path, and whether the path you typed was already absolute. With no argument, print a usage line and exit with code 1. It never touches the disk: path only works with text.

$ node fileinfo.js ./notes/today.md
name:      today
extension: .md
folder:    ./notes
absolute:  /home/me/part2/notes/today.md
was absolute? no
Hint

Take the argument with process.argv.slice(2). path.parse() gives you name, ext and dir in one call; path.resolve() turns it into an absolute path; path.isAbsolute() answers the last line.

Solution 
fileinfo.jsconst path = require("node:path");

const [input] = process.argv.slice(2);

if (!input) {
  console.log("Usage: node fileinfo.js <path>");
  process.exitCode = 1;
} else {
  const { name, ext, dir } = path.parse(input);
  console.log(`name:      ${name}`);
  console.log(`extension: ${ext || "(none)"}`);
  console.log(`folder:    ${dir || "."}`);
  console.log(`absolute:  ${path.resolve(input)}`);
  console.log(`was absolute? ${path.isAbsolute(input) ? "yes" : "no"}`);
}

Stretch goals: accept several paths at once and print a block for each; add a --json flag with util.parseArgs that prints the result as JSON; switch the file to ES Modules and replace require with import.
