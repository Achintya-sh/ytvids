Events module: emit and on

Big idea

An EventEmitter lets one part of your code announce that something happened (emit) and any number of other parts react (on), without knowing about each other. It's the pattern Node itself is built on: servers emit "request", streams emit "data", readline emits "line".

Analogy

A YouTube channel. Viewers subscribe (on). When the creator uploads (emit), every subscriber gets notified with the video (the data). The creator doesn't need to know who's subscribed. If you subscribe after the upload, you miss that notification.

const EventEmitter = require("events");   // the module exports the class
const shop = new EventEmitter();           // make an emitter object

// 1. Register listeners FIRST
shop.on("order", (item, qty) => {
  console.log(`Email: you ordered ${qty} × ${item}`);
});
shop.on("order", (item) => {
  console.log(`Stock: reduce ${item}`);
});
shop.once("order", () => {
  console.log("First order bonus!");         // runs only the first time
});

// 2. Then emit, passing any data as extra arguments
shop.emit("order", "pizza", 2);
shop.emit("order", "pasta", 1);

Email: you ordered 2 × pizza
Stock: reduce pizza
First order bonus!
Email: you ordered 1 × pasta
Stock: reduce pasta
new EventEmitter()creates an object that keeps a list of listeners per event name. on(name, fn)adds fn to that name's list. Alias: addListener. emit(name, ...args)calls every listener for name, in order, passing args. Returns true if there were listeners. once(name, fn)listener removes itself after its first run. off(name, fn)removes a listener. You need a reference to the same function, so use a named function. Alias: removeListener. listenerCount(name)how many listeners are registered.
Lab: event emitter simulator

Try emitting before adding any listeners: nothing happens. Then add a few and emit again. Add a once listener and emit twice.

Building your own emitter class

The real-world pattern is to extend EventEmitter so your class can emit its own events.

const EventEmitter = require("events");

class Timer extends EventEmitter {
  start(seconds) {
    this.emit("start", seconds);
    setTimeout(() => this.emit("done"), seconds * 1000);
  }
}

const t = new Timer();
t.on("start", (s) => console.log(`Started ${s}s timer`));
t.on("done", () => console.log("Time's up!"));
t.start(2);
The special "error" event

If something emits "error" and nobody is listening for it, Node throws and crashes. Always add emitter.on("error", err => …) on emitters that might fail.

Two things real projects run into New

Waiting for an event with await

const { EventEmitter, once } = require("node:events");
const db = new EventEmitter();

async function start() {
  setTimeout(() => db.emit("ready", "connected"), 500);
  const [status] = await once(db, "ready");   // resolves with emit's arguments, as an array
  console.log("DB is", status);                // DB is connected
}
start();

The memory-leak warning

By default Node warns when more than 10 listeners are attached to one event on one emitter: MaxListenersExceededWarning: Possible EventEmitter memory leak detected. It’s almost always a bug, typically calling on() inside a request handler so a new listener piles up on every request. Fix the bug; only raise the limit with emitter.setMaxListeners(n) when you truly need more.

Exam traps
  • Emitting before on is registered: the event is lost. Order matters.
  • Event names must match exactly, including case: "Login" ≠ "login".
  • emit is synchronous: all listeners finish before the line after emit runs.
  • require("events") gives the class itself; you need new.

Readline module: rl.question

Big idea

readline lets your program ask the user something in the terminal and wait for their typed answer. You connect it to the keyboard (process.stdin) and screen (process.stdout), ask with rl.question, and must close it when done or the program never exits.

Analogy

A phone call. createInterface dials. question asks something and waits for the reply (the callback is "what to do when they answer"). close hangs up. Forget to hang up and the line stays open forever.

ask.jsconst readline = require("readline");

const rl = readline.createInterface({
  input: process.stdin,     // read from keyboard
  output: process.stdout    // write prompts to terminal
});

rl.question("What's your name? ", (name) => {
  console.log(`Hello, ${name}!`);
  rl.close();               // hang up → program can exit
});

console.log("(this prints BEFORE you answer — question doesn't block)");
createInterfacebuilds the reader. It's an EventEmitter (stop 7). rl.question(prompt, cb)prints prompt, waits for Enter, then calls cb(answer). The answer is always a string. rl.close()stops listening to the keyboard. Emits "close".

Asking several questions

  
Because each answer arrives in a callback, the next question has to go inside the previous callback. Nesting gets deep fast ("callback hell").


rl.question("Name? ", (name) => {
  rl.question("Age? ", (age) => {
    console.log(`${name} is ${Number(age)} years old`);
    rl.close();
  });
});


  
The cleaner way: the promise version


const readline = require("readline/promises");   // note: /promises

async function main() {
  const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
  const name = await rl.question("Name? ");
  const age  = await rl.question("Age? ");
  console.log(`${name} is ${Number(age)} years old`);
  rl.close();
}
main();

Read a big file line by line New

  
readline works on any stream, not just the keyboard. Give it fs.createReadStream and you can process a huge log file one line at a time, without loading the whole file into memory.


count-errors.jsconst fs = require("node:fs");
const readline = require("node:readline");

async function countErrors(file) {
  const rl = readline.createInterface({
    input: fs.createReadStream(file),
    crlfDelay: Infinity          // treat \r\n (Windows line endings) as one line break
  });
  let total = 0, errors = 0;
  for await (const line of rl) { // one line per loop
    total++;
    if (line.includes("ERROR")) errors++;
  }
  console.log(`${errors} errors in ${total} lines`);
}

countErrors(process.argv[2]).catch(err => console.error(err.message));



$ node count-errors.js server.log
12 errors in 48210 lines

  
The for await loop ends, and the interface closes, when the file runs out.

FS module: read, write, append

  
Big idea
fs (file system) reads and writes files on disk. Every operation comes in three flavours: synchronous (blocks until done), callback (calls you back when done), and promise (works with await). Write replaces a file's contents; append adds to the end.

  
Analogy
A notebook page. readFile: read the page. writeFile: tear the page out and write a fresh one (old text gone). appendFile: write on the next empty line (old text kept). Both write and append create the page if it doesn't exist; read fails if it doesn't.

The three flavours, side by side


const fs = require("fs");
const path = require("path");
const file = path.join(__dirname, "notes.txt");

// ① SYNC — simple, but blocks the whole program while it works
try {
  const text = fs.readFileSync(file, "utf8");
  console.log(text);
} catch (err) {
  console.error("Read failed:", err.message);
}

// ② CALLBACK — "error-first": the first callback argument is always the error
fs.readFile(file, "utf8", (err, data) => {
  if (err) {
    return console.error("Read failed:", err.message);   // return stops here
  }
  console.log(data);
});

// ③ PROMISE — modern, use with async/await
const fsp = require("fs/promises");
async function show() {
  try {
    const data = await fsp.readFile(file, "utf8");
    console.log(data);
  } catch (err) {
    console.error(err.message);
  }
}


  
The "utf8" trap
Without the encoding, readFile gives you a Buffer (raw bytes, printed like <Buffer 48 65 6c 6c 6f>), not text. Always pass "utf8" or call data.toString().


  
Write and append


// Overwrites (or creates) the file
fs.writeFile(file, "First line\n", (err) => {
  if (err) return console.error(err);
  console.log("Saved");

  // Adds to the end (or creates). Put this INSIDE the callback so it runs after.
  fs.appendFile(file, "Second line\n", (err) => {
    if (err) return console.error(err);
    console.log("Appended");
  });
});

// Sync versions
fs.writeFileSync(file, "Fresh start\n");
fs.appendFileSync(file, "Another line\n");


  
Order isn't guaranteed with callbacks
If you call fs.writeFile(...) and then fs.appendFile(...) on the next line (not nested), they run at the same time and the append may happen before the write, which then wipes it. Nest them, use the sync versions, or await the promise versions in sequence.

Pattern: a JSON file as a mini database

  
Very likely in a coding exam: store an array of objects in a .json file.


store.jsconst fs = require("fs");
const path = require("path");
const DB = path.join(__dirname, "todos.json");

function load() {
  if (!fs.existsSync(DB)) return [];                 // no file yet → empty list
  return JSON.parse(fs.readFileSync(DB, "utf8"));    // text → array
}

function save(todos) {
  fs.writeFileSync(DB, JSON.stringify(todos, null, 2));  // array → pretty text
}

const todos = load();
todos.push({ id: Date.now(), text: "Revise fs", done: false });
save(todos);


  
JSON.stringify(value, null, 2): the null means "no filter", the 2 means indent with 2 spaces so the file is readable.

  
Streams: big files in small pieces New

  
Analogy
readFile fills a whole bucket and then carries it. A stream is a pipe: the water flows through a little at a time, so a 2 GB file never has to fit in memory at once.


copy-big.jsconst fs = require("node:fs");
const { pipeline } = require("node:stream/promises");

async function copy(src, dest) {
  await pipeline(
    fs.createReadStream(src),    // reads in chunks (64 KB by default)
    fs.createWriteStream(dest)   // writes each chunk as it arrives
  );
  console.log("Copied");
}

copy("big-video.mp4", "backup.mp4").catch(err => console.error(err.message));


  
pipeline connects the streams, slows the reader down when the writer falls behind, and reports any error in one place. Streams are EventEmitters too: they emit "data", "end" and "error". Video streaming and file uploads work this way.

HTTP module: request and response

  
Big idea
The built-in http module creates a web server with no extra packages. You give http.createServer one function; Node calls it for every request with two objects: req (what the client asked for) and res (what you'll send back). You must always finish with res.end(). Express (next line) is built on top of exactly this.

  
Analogy
req is a letter that arrived: who sent it, what it says, which department it's for. res is a blank reply envelope. You write the status, the headers and the body, then res.end() seals and posts it. If you never seal it, the sender waits forever.



server.jsconst http = require("http");

const server = http.createServer((req, res) => {
  console.log(req.method, req.url);        // e.g. "GET /about"

  if (req.method === "GET" && req.url === "/") {
    res.writeHead(200, { "Content-Type": "text/html" });
    res.end("<h1>Home</h1>");
  } else if (req.method === "GET" && req.url === "/api/users") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify([{ id: 1, name: "Asha" }]));   // must be a string!
  } else {
    res.writeHead(404, { "Content-Type": "text/plain" });
    res.end("Not found");
  }
});

server.listen(3000, () => {
  console.log("Server on http://localhost:3000");
});



  
The req object (read it)
    
    
  • req.method: "GET", "POST"…
    • 
    
  • req.url: path + query, e.g. "/users?page=2"
    • 
    
  • req.headers: object, lower-case keys, e.g. req.headers["content-type"]
    • 
    
  • Body: not ready yet; arrives in chunks (see below)
    • 
  
The res object (write it)
    
    
  • res.statusCode = 404
    • 
    
  • res.setHeader("Content-Type", "text/plain")
    • 
    
  • res.writeHead(200, {...}): status + headers in one go
    • 
    
  • res.write("part"): send some body (can repeat)
    • 
    
  • res.end("last part"): finish. Required, once.
    •

Parse the URL properly New

  
The lab showed that req.url includes the query string. The built-in URL class splits it apart for you.


// request: GET /api/users?page=2&sort=name
const url = new URL(req.url, `http://${req.headers.host}`);

url.pathname                     // "/api/users"
url.searchParams.get("page")     // "2"   (still a string)
url.searchParams.get("missing")  // null

if (req.method === "GET" && url.pathname === "/api/users") {
  const page = Number(url.searchParams.get("page") ?? 1);
  // …
}


  
The second argument is a base, needed because req.url is only a path. Express does exactly this and hands you the result as req.query.


  
Reading a POST body by hand

  
Request bodies arrive as a stream of chunks (req is an EventEmitter). You collect them on "data" and use them on "end". Express's express.json() does this for you.


if (req.method === "POST" && req.url === "/api/users") {
  let body = "";
  req.on("data", (chunk) => { body += chunk; });   // pieces arrive
  req.on("end", () => {                            // all arrived
    try {
      const user = JSON.parse(body);
      res.writeHead(201, { "Content-Type": "application/json" });
      res.end(JSON.stringify({ id: 2, ...user }));
    } catch {
      res.writeHead(400);
      res.end("Invalid JSON");
    }
  });
  return;   // don't fall through to other branches
}

Serve an HTML file with fs + path New


site.jsconst http = require("node:http");
const fs = require("node:fs/promises");
const path = require("node:path");

http.createServer(async (req, res) => {
  if (req.method === "GET" && req.url === "/") {
    try {
      const html = await fs.readFile(path.join(__dirname, "public", "index.html"), "utf8");
      res.writeHead(200, { "Content-Type": "text/html; charset=utf-8" });
      return res.end(html);
    } catch {
      res.writeHead(500, { "Content-Type": "text/plain" });
      return res.end("Could not read index.html");
    }
  }
  res.writeHead(404, { "Content-Type": "text/plain" });
  res.end("Not found");
}).listen(3000);


  
Three modules working together: http receives, path builds the file location, fs reads it. This is a tiny version of what express.static does for a whole folder.

A notes API with only core modules New

  
Big idea
Five modules, one small program. process gives the port, path locates the data file, fs stores notes as JSON, events lets logging react to new notes without the route knowing about it, and http answers GET /notes and POST /notes. Notes survive a restart because they live in a file.

notes-api.jsconst http = require("node:http");
const fs = require("node:fs/promises");
const path = require("node:path");
const { EventEmitter } = require("node:events");

const PORT = Number(process.env.PORT ?? 3000);          // process (video 2)
const DB = path.join(__dirname, "notes.json");          // path (video 2)
const LOG = path.join(__dirname, "notes.log");
const bus = new EventEmitter();                         // events (stop 7)

// ---- storage: a JSON file as a mini database (stop 9)
async function loadNotes() {
  try {
    return JSON.parse(await fs.readFile(DB, "utf8"));
  } catch (err) {
    if (err.code === "ENOENT") return [];               // no file yet → empty list
    throw err;
  }
}
async function saveNotes(notes) {
  await fs.writeFile(DB, JSON.stringify(notes, null, 2));
}

// ---- logging reacts to an event; the route doesn't know it exists
bus.on("note:created", (note) => {
  const line = `${new Date().toISOString()} created #${note.id}\n`;
  fs.appendFile(LOG, line).catch((err) => console.error("log failed:", err.message));
});

// ---- small http helpers (stop 10)
function sendJSON(res, status, data) {
  res.writeHead(status, { "Content-Type": "application/json" });
  res.end(JSON.stringify(data));
}
function readBody(req) {
  return new Promise((resolve, reject) => {
    let body = "";
    req.on("data", (chunk) => (body += chunk));
    req.on("end", () => resolve(body));
    req.on("error", reject);
  });
}

const server = http.createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);
  try {
    if (req.method === "GET" && url.pathname === "/notes") {
      return sendJSON(res, 200, await loadNotes());
    }
    if (req.method === "POST" && url.pathname === "/notes") {
      let input;
      try { input = JSON.parse(await readBody(req)); }
      catch { return sendJSON(res, 400, { error: "Body must be JSON" }); }
      if (!input?.text) return sendJSON(res, 400, { error: "text is required" });

      const notes = await loadNotes();
      const note = { id: Date.now(), text: input.text };
      notes.push(note);
      await saveNotes(notes);
      bus.emit("note:created", note);
      return sendJSON(res, 201, note);
    }
    sendJSON(res, 404, { error: "Not found" });
  } catch (err) {
    console.error(err);
    sendJSON(res, 500, { error: "Server error" });
  }
});

server.listen(PORT, () => console.log(`Notes API on http://localhost:${PORT}`));
process.on("SIGINT", () => server.close(() => process.exit(0)));   // Ctrl+C


  

    loadNotes()treats a missing file (ENOENT) as “no notes yet” instead of crashing; any other error is real and goes to the 500 handler.
    bus.emit(…)the route only announces what happened. Add more listeners later (email, analytics) without touching the route.
    input?.textoptional chaining from video 1: a body of null gets a clean 400 instead of a crash.
    return sendJSON(…)every response is followed by return, so no request is ever answered twice.

Problem 1 · process.argv + fs + path
Command-line todo list

  
Build todo.js that stores todos in todos.json next to the script:


node todo.js add "Buy milk"   # → Added #1: Buy milk
node todo.js list             # → 1. [ ] Buy milk
node todo.js done 1           # → Marked #1 done
node todo.js remove 1         # → Removed #1
node todo.js                  # → Usage: add <text> | list | done <id> | remove <id>

  
Hint
Destructure const [cmd, ...rest] = process.argv.slice(2). Write load() and save() helpers with readFileSync/writeFileSync and JSON.parse/stringify. Use a switch on cmd. Remember ids from argv are strings.

  
Solution

todo.jsconst fs = require("fs");
const path = require("path");
const FILE = path.join(__dirname, "todos.json");

const load = () => (fs.existsSync(FILE) ? JSON.parse(fs.readFileSync(FILE, "utf8")) : []);
const save = (todos) => fs.writeFileSync(FILE, JSON.stringify(todos, null, 2));

const [cmd, ...rest] = process.argv.slice(2);
const todos = load();

switch (cmd) {
  case "add": {
    const text = rest.join(" ");
    if (!text) { console.log("Please provide todo text"); process.exit(1); }
    const id = todos.length ? Math.max(...todos.map(t => t.id)) + 1 : 1;
    todos.push({ id, text, done: false });
    save(todos);
    console.log(`Added #${id}: ${text}`);
    break;
  }
  case "list":
    if (!todos.length) console.log("No todos yet");
    todos.forEach(t => console.log(`${t.id}. [${t.done ? "x" : " "}] ${t.text}`));
    break;
  case "done": {
    const todo = todos.find(t => t.id === Number(rest[0]));
    if (!todo) { console.log("Todo not found"); process.exit(1); }
    todo.done = true;
    save(todos);
    console.log(`Marked #${todo.id} done`);
    break;
  }
  case "remove": {
    const id = Number(rest[0]);
    const left = todos.filter(t => t.id !== id);
    if (left.length === todos.length) { console.log("Todo not found"); process.exit(1); }
    save(left);
    console.log(`Removed #${id}`);
    break;
  }
  default:
    console.log("Usage: add  | list | done  | remove ");
}


  
Problem 2 · readline + fs append
Terminal quiz that saves scores

  
Ask the user their name, then three questions one after another. Show their score out of 3, and append a line like Asha: 2/3 (2026-10-14T…) to results.txt.

  
Hint
Use readline/promises with async/await to avoid nesting. Loop over an array of { q, a } objects. Compare with answer.trim().toLowerCase(). Call rl.close() at the end.

  
Solution

quiz.jsconst readline = require("readline/promises");
const fs = require("fs");
const path = require("path");

const questions = [
  { q: "Which method sends JSON in Express? ", a: "res.json" },
  { q: "Which module joins paths? ", a: "path" },
  { q: "Status code for Created? ", a: "201" }
];

async function main() {
  const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
  const name = (await rl.question("Your name: ")).trim() || "Anonymous";
  let score = 0;

  for (const { q, a } of questions) {
    const answer = await rl.question(q);
    if (answer.trim().toLowerCase() === a) { console.log("✓ Correct"); score++; }
    else console.log(`✗ Answer: ${a}`);
  }

  rl.close();
  console.log(`${name}, you scored ${score}/${questions.length}`);
  const line = `${name}: ${score}/${questions.length} (${new Date().toISOString()})\n`;
  fs.appendFileSync(path.join(__dirname, "results.txt"), line);
}

main();

Problem 3 · events
Bank account that emits events

  
Create a BankAccount class that extends EventEmitter with deposit(amount) and withdraw(amount). Emit "deposit", "withdraw", or "insufficient" (if the balance is too low) with useful data. Attach listeners that log messages and test it.

  
Solution

bank.jsconst EventEmitter = require("events");

class BankAccount extends EventEmitter {
  constructor(owner, balance = 0) {
    super();                          // required when extending
    this.owner = owner;
    this.balance = balance;
  }
  deposit(amount) {
    this.balance += amount;
    this.emit("deposit", amount, this.balance);
  }
  withdraw(amount) {
    if (amount > this.balance) {
      return this.emit("insufficient", amount, this.balance);
    }
    this.balance -= amount;
    this.emit("withdraw", amount, this.balance);
  }
}

const acc = new BankAccount("Asha", 100);
acc.on("deposit", (amt, bal) => console.log(`+₹${amt} → balance ₹${bal}`));
acc.on("withdraw", (amt, bal) => console.log(`-₹${amt} → balance ₹${bal}`));
acc.on("insufficient", (amt, bal) => console.log(`✗ Can't withdraw ₹${amt}, only ₹${bal}`));
acc.once("deposit", () => console.log("🎉 First deposit!"));

acc.deposit(50);    // +₹50 → balance ₹150, then 🎉 First deposit!
acc.withdraw(500);  // ✗ Can't withdraw ₹500, only ₹150
acc.withdraw(30);   // -₹30 → balance ₹120


  
Problem 4 · http module
A server with no Express

  
Using only http: GET / returns HTML, GET /api/time returns { "time": "…" }, POST /api/echo returns the JSON body it was sent with status 201 (400 if invalid JSON), and anything else returns a 404 JSON error.

  
Solution

server.jsconst http = require("http");

const sendJson = (res, status, data) => {
  res.writeHead(status, { "Content-Type": "application/json" });
  res.end(JSON.stringify(data));
};

const server = http.createServer((req, res) => {
  const { method } = req;
  const url = req.url.split("?")[0];        // ignore query string

  if (method === "GET" && url === "/") {
    res.writeHead(200, { "Content-Type": "text/html" });
    return res.end("<h1>Welcome</h1>");
  }
  if (method === "GET" && url === "/api/time") {
    return sendJson(res, 200, { time: new Date().toISOString() });
  }
  if (method === "POST" && url === "/api/echo") {
    let body = "";
    req.on("data", chunk => (body += chunk));
    req.on("end", () => {
      try { sendJson(res, 201, JSON.parse(body)); }
      catch { sendJson(res, 400, { error: "Invalid JSON" }); }
    });
    return;
  }
  sendJson(res, 404, { error: `Cannot ${method} ${url}` });
});

server.listen(3000, () => console.log("http://localhost:3000"));
