JavaScript essentials for backend

Big idea

JavaScript is the language. Node.js lets it run outside the browser. Backend code mostly does five things: store data in variables, group it in objects and arrays, transform it with functions, convert it to and from JSON, and wait for slow things (files, databases) with async/await.

1.1 Variables: boxes with labels

Analogy

A variable is a labelled box. const is a box that's been taped shut: you can't put a different thing in it. let is an open box: you can swap what's inside.

const port = 3000;      // can't be reassigned
let count = 0;          // can change
count = count + 1;      // fine, count is now 1
// port = 4000;         // TypeError: Assignment to constant variable.

const user = { name: "Asha" };
user.name = "Ravi";     // allowed! the box is taped, but the object inside can still change
Exam trap

const stops reassignment, not changes inside objects and arrays. const arr = []; arr.push(1) works. Avoid var; it ignores block scope and causes bugs.

1.3 Comparisons and truthiness

5 == "5"    // true  — loose: converts types first (avoid)
5 === "5"   // false — strict: type AND value must match (always use this)

// "Falsy" values behave like false in an if:
// false, 0, "", null, undefined, NaN
// Everything else is "truthy", including "0", [], {}
if (!user) { /* runs when user is undefined or null */ }

1.4 Functions: reusable machines

Analogy

A function is a machine. Parameters are the input slots, return is the output chute. Calling the function is pressing the start button.

// 1. Function declaration
function add(a, b) {
  return a + b;
}

// 2. Arrow function (same thing, shorter — used everywhere in Express)
const add2 = (a, b) => {
  return a + b;
};

// 3. Arrow with implicit return (one expression, no braces)
const add3 = (a, b) => a + b;

// 4. Default parameter
const greet = (name = "stranger") => `Hello, ${name}`;

add(2, 3);   // 5
greet();     // "Hello, stranger"

Callbacks: the most important idea for Node

A callback is a function you hand to another function, which calls it later. Every Express route handler, every event listener and every fs callback is one.

function doTwice(callback) {
  callback();
  callback();
}
doTwice(() => console.log("hi"));   // prints hi, hi

// You've seen this shape already:
app.get("/", (req, res) => { res.send("home"); });
//            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ a callback Express calls for each request

1.5 Objects and arrays

const book = { id: 7, title: "Dune", tags: ["sci-fi"] };
book.title          // "Dune"        dot notation
book["title"]       // "Dune"        bracket notation (needed when the key is in a variable)
const key = "id";
book[key]           // 7
book.year = 1965;   // add a property
delete book.tags;   // remove a property

const nums = [10, 20, 30];
nums[0]             // 10  (arrays start at index 0)
nums.length         // 3
nums.push(40);      // add to the end   → [10,20,30,40]
nums.pop();         // remove from end  → [10,20,30]

1.7 Destructuring, spread and template literals

// Object destructuring: pull properties into variables
const { id, title } = book;          // id = 7, title = "Dune"
const { name, email } = req.body;    // you'll write this constantly in Express

// Array destructuring
const [first, second] = [10, 20];    // first = 10

// Spread: copy and merge
const updated = { ...book, title: "Dune Messiah" }; // copy book, override title
const all = [...nums, 99];                          // copy array, add 99

// Rest: collect "the rest" into an array
const [cmd, ...args] = ["add", "milk", "eggs"];     // cmd="add", args=["milk","eggs"]

// Template literals: backticks + ${ } for inserting values
const msg = `Server running on port ${port}`;

1.8 JSON: how data travels

Analogy

You can't mail a living object; you write it down as text, send the letter, and the receiver rebuilds it. JSON.stringify writes the letter. JSON.parse rebuilds the object.

const obj = { id: 1, done: false };
const text = JSON.stringify(obj);  // '{"id":1,"done":false}'  — a string
const back = JSON.parse(text);     // { id: 1, done: false }  — an object again
back.done                          // false
// JSON rules: keys in "double quotes", no functions, no trailing commas, no comments.

1.9 Async: waiting without freezing

Analogy

You order pizza (start a slow task), get a receipt (a Promise), and keep watching TV instead of standing at the door. When the doorbell rings, you handle the pizza. await means "pause this function until the pizza arrives" while the rest of the program keeps going.

// A Promise is a placeholder for a value that arrives later.
// It is pending, then either fulfilled (success) or rejected (error).

// Style 1: .then / .catch
fetchUser(1)
  .then(user => console.log(user))
  .catch(err => console.error(err));

// Style 2: async / await (cleaner — use this)
async function show() {
  try {
    const user = await fetchUser(1);   // waits here
    console.log(user);
  } catch (err) {
    console.error("Failed:", err.message);
  }
}
// Rules: await only works inside an async function (or top level of an ES module).
// An async function ALWAYS returns a Promise.

Predict the order

console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
Show the answer
A
C
B

Even with 0 ms, setTimeout's callback waits until the current code finishes. Synchronous code always runs first, start to end; async callbacks run afterwards.

1.10 Errors

try {
  JSON.parse("not json");        // throws
} catch (err) {
  console.log(err.message);      // "Unexpected token o in JSON..."
} finally {
  console.log("always runs");
}
throw new Error("Something broke");  // create your own error

1.11 Optional chaining and nullish coalescing New

Request data is often incomplete. These two operators let you read it without crashing and give sensible defaults.

const body = { user: { name: "Asha" } };

body.user?.name            // "Asha"
body.address?.city         // undefined  (no crash)
body.address.city          // TypeError: Cannot read properties of undefined

// ?? gives a fallback ONLY for null or undefined
const retries = 0;
retries || 3               // 3  ← || treats 0, "" and false as "missing"
retries ?? 3               // 0  ← ?? keeps real values like 0 and ""

const port = process.env.PORT ?? 3000;
When to use which

Use ?? for defaults whenever 0, "" or false are valid values. Use ?. when part of an object might really be missing. Don’t sprinkle ?. everywhere: if a value must exist, a crash tells you about the bug sooner.

1.12 Running async jobs together New

Two awaits in a row run one after the other. If the jobs don’t depend on each other, start them together with Promise.all.

// One after another: about 2 seconds if each call takes 1 second
const user = await getUser(1);
const posts = await getPosts(1);

// Together: about 1 second
const [user2, posts2] = await Promise.all([getUser(1), getPosts(1)]);

// If any one rejects, Promise.all rejects.
// Promise.allSettled waits for all and tells you which succeeded.
Remember
  • const by default, let when it changes, never var.
  • Always ===. Input from URLs and the terminal is a string: convert with Number().
  • find returns the item or undefined; findIndex returns the index or -1.
  • await needs async; wrap it in try/catch.

Intro to backend

Big idea

The frontend is what runs on the user's device (the page they see). The backend is a program on a server that receives requests, does the work (check passwords, read a database, apply rules) and sends back a response. They talk over HTTP.

Analogy

A restaurant. The dining room is the frontend: menus, tables, what customers see. The kitchen is the backend: customers never go in, but it does the real work. The waiter is HTTP, carrying orders (requests) in and dishes (responses) out. The pantry is the database.

Why have a backend at all?

  • Security: anything in the frontend can be read by the user. Passwords, database credentials and secret keys must live on the server.
  • Shared, permanent data: your posts must still exist when you log in from a different phone. The server stores them in a database.
  • Rules you can trust: "you can't withdraw more than your balance" must be enforced where users can't edit the code.

The anatomy of a URL

How a request finds your server: IP, DNS and ports

TermThink of it asWhat it is
IP addressA postal addressThe number that identifies a machine on a network, e.g. 142.250.183.14.
DNSYour phone's contacts appTurns a name like google.com into an IP address, so nobody has to remember numbers.
localhost"My own house"The name for your own computer. It resolves to 127.0.0.1. Your dev server lives here.
PortA flat number inside the buildingOne machine runs many programs; the port says which one gets the message. HTTP defaults to 80, HTTPS to 443, and dev servers commonly use 3000.

So http://localhost:3000 means "on this computer, deliver to the program listening on port 3000". app.listen(3000) is your program claiming that port.

HTTPS New is the same HTTP sent through an encrypted connection (TLS), on port 443 by default. Same methods, same status codes, but nobody between you and the server can read or change the messages.

Exam trap: EADDRINUSE

Only one program can listen on a port at a time. Start a second server on 3000 (often an old terminal still running) and Node crashes with Error: listen EADDRINUSE: address already in use :::3000. Stop the old one with Ctrl + C, or use another port.

Remember
  • Client sends a request (method + URL + headers + optional body). Server sends a response (status + headers + body).
  • HTTP is stateless: each request stands alone; the server doesn't remember the last one unless you add sessions or tokens.
  • Backend APIs usually speak JSON.

Intro to Node.js

Big idea

Node.js is a runtime: a program that runs JavaScript outside the browser. It takes Chrome's V8 engine (which turns JS into machine code) and adds abilities browsers don't allow, like reading files, starting servers and reading command-line arguments. It is not a language and not a framework.

Analogy

JavaScript is an engine. The browser puts that engine in a car built for driving around web pages (it has document, window, buttons). Node puts the same engine in a truck built for hauling (it has fs, http, process). Same engine, different vehicle, different tools.

Why Node is fast for servers

Node runs your JavaScript on a single thread but uses non-blocking I/O. When your code asks to read a file or query a database, Node hands that job off and moves on to the next request instead of waiting. When the job finishes, your callback runs.

Analogy

One café cashier takes your order, passes it to the baristas, and serves the next customer straight away. They don't stand frozen while your coffee brews. That's non-blocking. A blocking cashier would make the whole queue wait for each coffee.

Two parts make this work. V8 runs your JavaScript. libuv, a C library built into Node, does the waiting: it asks the operating system to handle network and file I/O, and keeps a small pool of background threads for slow jobs like reading files. When a job finishes, libuv queues your callback and V8 runs it. You never call libuv yourself; fs, http and the other core modules use it for you.

New in 2026: one release a year
Starting with Node.js 27, there is one major release each April, it becomes LTS in October, and every release becomes LTS. The old rule “only even numbers are LTS” ends with Node 26. If you only ever install LTS, little changes for you beyond the numbers.

npm and package.json

  
npm (Node Package Manager) downloads other people's code (packages) such as Express. package.json is your project's ID card: name, scripts and dependency list.


npm init -y                 # create package.json with defaults
npm install express         # add a dependency  (short: npm i express)
npm install -D nodemon      # add a dev-only dependency
npm install                 # reinstall everything listed in package.json
npm run dev                 # run the "dev" script
npm start                   # shortcut for the "start" script



package.json{
  "name": "my-api",
  "version": "1.0.0",
  "main": "index.js",
  "type": "commonjs",               // or "module" to use import/export
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js"       // restarts automatically when you save
  },
  "dependencies": { "express": "^5.1.0" },
  "devDependencies": { "nodemon": "^3.1.0" }
}
